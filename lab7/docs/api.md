# Описание API

Адрес сервера: http://localhost:8000. Ответы передаются в JSON. Для POST, PUT и PATCH передаётся объект JSON с заголовком Content-Type: application/json. Авторизации нет, используется локальный учебный сервер.

## Таблица запросов

| Метод | Адрес | Назначение | Код |
|---|---|---|---|
| GET | /api/appointments | Список приёмов | 200 |
| GET | /api/appointments/{id} | Один приём | 200 |
| POST | /api/appointments | Создать приём | 201 |
| PUT, PATCH | /api/appointments/{id} | Изменить приём | 200 |
| DELETE | /api/appointments/{id} | Удалить приём | 204 |
| GET | /api/animals | Список животных | 200 |
| GET | /api/animals/{id} | Одно животное | 200 |
| POST | /api/animals | Добавить животное | 201 |
| PUT, PATCH | /api/animals/{id} | Изменить животное | 200 |
| DELETE | /api/animals/{id} | Удалить животное | 204 |
| GET | /api/owners | Список владельцев | 200 |
| GET | /api/owners/{id} | Один владелец | 200 |
| POST | /api/owners | Добавить владельца | 201 |
| PUT, PATCH | /api/owners/{id} | Изменить владельца | 200 |
| DELETE | /api/owners/{id} | Удалить владельца | 204 |
| GET | /api/animals/{id}/appointments | Приёмы животного | 200 |

## Поля

| Ресурс | Поле | Тип | Обязательное при создании | Описание |
|---|---|---|---|---|
| Приём | animal_id | Целое число | Да | Номер существующего животного |
| Приём | title | Строка | Да | Причина обращения, минимум 3 символа |
| Приём | doctor | Строка | Да | Непустое имя врача |
| Приём | date | Строка | Да | Дата и время в виде 2026-11-01T10:00 |
| Приём | status | Строка | Нет | scheduled по умолчанию, done или cancelled |
| Животное | name | Строка | Да | Кличка, минимум 3 символа |
| Животное | owner_id | Целое число | Да | Номер существующего владельца |
| Владелец | name | Строка | Да | ФИО, минимум 3 символа |
| Владелец | phone | Строка | Да | Непустой телефон |
| Владелец | email | Строка | Нет | Правильная почта либо пустая строка по умолчанию |

Поле id назначает сервер. Номера в JSON передаются числами, не строками. Неизвестные поля игнорируются. При обновлении остальные поля сохраняются; PUT и PATCH работают одинаково по условиям учебного задания. Пустой объект при обновлении не меняет данные.

Примеры показывают формат, а не протокол испытаний. Число записей и новые номера зависят от данных. В примерах списков показана одна запись.

## Общие ошибки

- 400 — неправильный JSON или вместо объекта передан список.
- 404 — неизвестный адрес или номер записи.
- 405 — метод не поддерживается; Allow содержит доступные методы.
- 409 — запрещено удаление связанной записи.
- 422 — неправильные поля.
- 500 — ошибка чтения или сохранения файла.

Формат ошибки одинаковый:
```json
{"error":"Ошибка проверки данных","errors":{"name":"ФИО — не короче трёх символов"}}
```

Без отдельных ошибок полей errors является пустым объектом. Content-Type ответа с JSON — application/json; charset=utf-8.

## Приёмы

### GET /api/appointments

Назначение: получить список. Тела нет. Необязательные параметры: status — статус, animal_id — номер животного, q — часть причины обращения без учёта регистра. Условия работают одновременно.

Пример: GET /api/appointments?status=scheduled&animal_id=1&q=осмотр

Ответ 200:
```json
[{"id":1,"animal_id":1,"title":"Плановый осмотр","doctor":"Иванова","date":"2026-11-01T10:00","status":"scheduled"}]
```
При отсутствии совпадений — []. Ошибки: 422 при передаче массива вместо строки параметра, 405, 500.

### GET /api/appointments/{id}

Назначение: получить приём. id — номер в адресе, тела нет.

Пример: GET /api/appointments/1

Ответ 200:
```json
{"id":1,"animal_id":1,"title":"Плановый осмотр","doctor":"Иванова","date":"2026-11-01T10:00","status":"scheduled"}
```
Ошибки: 404, 405, 500.

### POST /api/appointments

Назначение: создать приём. Поля тела и обязательность указаны в таблице. Параметров адреса нет.

Пример тела:
```json
{"animal_id":1,"title":"Плановый осмотр","doctor":"Иванова","date":"2026-11-10T12:00"}
```
Ответ 201, заголовок Location: /api/appointments/7:
```json
{"status":"scheduled","animal_id":1,"title":"Плановый осмотр","doctor":"Иванова","date":"2026-11-10T12:00","id":7}
```
Ошибки: 400, 422, 405, 500.

### PATCH /api/appointments/{id} и PUT /api/appointments/{id}

Назначение: изменить приём. id — номер в адресе; тело содержит изменяемые поля из таблицы.

Пример: PATCH /api/appointments/1
```json
{"status":"done"}
```
Ответ 200:
```json
{"id":1,"animal_id":1,"title":"Плановый осмотр","doctor":"Иванова","date":"2026-11-01T10:00","status":"done"}
```
Ошибки: 400, 404, 422, 405, 500.

### DELETE /api/appointments/{id}

Назначение: удалить приём. id — номер в адресе, тела нет.

Пример: DELETE /api/appointments/1

Ответ 204 без тела. Ошибки: 404, 405, 500. Физическое удаление не является отменой приёма. Для отмены можно изменить status на cancelled.

## Животные

### GET /api/animals

Назначение: получить список животных. Параметров и тела нет.

Пример: GET /api/animals

Ответ 200:
```json
[{"id":1,"name":"Рекс","owner_id":1}]
```
Ошибки: 405, 500.

### GET /api/animals/{id}

Назначение: получить животное. id — номер в адресе, тела нет.

Пример: GET /api/animals/1

Ответ 200:
```json
{"id":1,"name":"Рекс","owner_id":1}
```
Ошибки: 404, 405, 500.

### POST /api/animals

Назначение: добавить животное. В теле обязательны name и owner_id. Параметров адреса нет.

Пример тела:
```json
{"name":"Тузик","owner_id":1}
```
Ответ 201, заголовок Location: /api/animals/4:
```json
{"name":"Тузик","owner_id":1,"id":4}
```
Ошибки: 400, 422, 405, 500.

### PATCH /api/animals/{id} и PUT /api/animals/{id}

Назначение: изменить животное. id — номер в адресе; тело содержит name и/или owner_id.

Пример: PATCH /api/animals/1
```json
{"name":"Рексик"}
```
Ответ 200:
```json
{"id":1,"name":"Рексик","owner_id":1}
```
Ошибки: 400, 404, 422, 405, 500.

### DELETE /api/animals/{id}

Назначение: удалить животное, у которого нет приёмов. id — номер в адресе, тела нет.

Пример: DELETE /api/animals/4

Ответ 204 без тела. Ошибки: 404, 409 при наличии приёмов, 405, 500.

### GET /api/animals/{id}/appointments

Назначение: получить приёмы животного. id — номер животного, тела нет.

Пример: GET /api/animals/1/appointments

Ответ 200:
```json
[{"id":1,"animal_id":1,"title":"Плановый осмотр","doctor":"Иванова","date":"2026-11-01T10:00","status":"scheduled"}]
```
Если приёмов нет — []. Ошибки: 404 при отсутствии животного, 405, 500.

## Владельцы

### GET /api/owners

Назначение: получить список владельцев. Параметров и тела нет.

Пример: GET /api/owners

Ответ 200:
```json
[{"id":1,"name":"Иванов И.И.","phone":"+79000000001","email":"ivanov@example.org"}]
```
Ошибки: 405, 500.

### GET /api/owners/{id}

Назначение: получить владельца. id — номер в адресе, тела нет.

Пример: GET /api/owners/1

Ответ 200:
```json
{"id":1,"name":"Иванов И.И.","phone":"+79000000001","email":"ivanov@example.org"}
```
Ошибки: 404, 405, 500.

### POST /api/owners

Назначение: добавить владельца. Обязательны name и phone; email необязателен. Параметров адреса нет.

Пример тела:
```json
{"name":"Иванов Иван","phone":"+79000000009"}
```
Ответ 201, заголовок Location: /api/owners/4:
```json
{"email":"","name":"Иванов Иван","phone":"+79000000009","id":4}
```
Ошибки: 400, 422, 405, 500.

### PATCH /api/owners/{id} и PUT /api/owners/{id}

Назначение: изменить владельца. id — номер в адресе; тело содержит изменяемые name, phone и/или email.

Пример: PATCH /api/owners/1
```json
{"phone":"+79000000009"}
```
Ответ 200:
```json
{"id":1,"name":"Иванов И.И.","phone":"+79000000009","email":"ivanov@example.org"}
```
Ошибки: 400, 404, 422, 405, 500.

### DELETE /api/owners/{id}

Назначение: удалить владельца без животных. id — номер в адресе, тела нет.

Пример: DELETE /api/owners/4

Ответ 204 без тела. Ошибки: 404, 409 при наличии животных, 405, 500.

## Пример curl

```sh
curl -i http://localhost:8000/api/appointments
```

Для отправки JSON сохраните тело нужного запроса в request.json в UTF-8:

```sh
curl -i -X POST -H "Content-Type: application/json" --data-binary @request.json http://localhost:8000/api/owners
```

В Windows PowerShell используйте curl.exe. Запросы создания, изменения и удаления меняют файлы в src/storage, поэтому проверяйте на учебной копии.
