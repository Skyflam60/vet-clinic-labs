# Описание API ветеринарной клиники

Адрес сервера: `http://localhost:8000`. Клиент открывается по адресу `http://localhost:8000/client/`, поэтому CORS не нужен. Тела запросов и ответов передаются в JSON с заголовком `Content-Type: application/json`. Данные хранятся в PostgreSQL (база `vetdb`, схема из ЛР №8).

## Авторизация

Все адреса `/api/...`, кроме входа, требуют токен в заголовке:

```
Authorization: Bearer <токен>
```

Без токена, с неверным, отозванным или просроченным токеном сервер отвечает `401 {"error": "Требуется авторизация"}` и заголовком `WWW-Authenticate: Bearer`. Токен действует 2 часа (`token_ttl` в `config/app.php`).

### POST /api/auth/login

Вход. Токен не нужен.

```json
{"email": "registrar@vet.example", "password": "123456"}
```

Ответ 200:

```json
{
  "token": "94f470b14771…(64 символа)",
  "expires_at": "2026-11-10T11:10:06+00:00",
  "user": {"id": 2, "name": "Светлана Регистратор", "email": "registrar@vet.example", "role": "registrar"}
}
```

Ошибки:
- 400 — тело не JSON;
- 422 — пустые email или password (`errors.email`, `errors.password`);
- 401 «Неверный email или пароль». Сообщение одно и то же для неверного пароля и несуществующей почты.

Почта сравнивается без учёта регистра. Хеш пароля в ответ не попадает.

### GET /api/auth/me

Возвращает пользователя, которому принадлежит токен: `{"id", "name", "email", "role"}`. Клиент вызывает его при открытии страницы, чтобы проверить сохранённый токен.

### POST /api/auth/logout

Выход: токен удаляется из таблицы `auth_tokens` и больше не действует. Ответ 204 без тела.

## Роли и права

| Действие | admin (администратор) | registrar (регистратор) | doctor (врач) |
|---|---|---|---|
| смотреть приёмы, животных, владельцев, врачей | да | да | да |
| записывать на приём и изменять приём (статус, время, врач) | да | да | да |
| удалять приём | да | нет (403) | нет (403) |
| добавлять и изменять животных и владельцев | да | да | нет (403) |
| удалять животных и владельцев | да | нет (403) | нет (403) |
| добавлять, изменять, удалять врачей | да | нет (403) | нет (403) |
| пользователи системы (`/api/users`), в том числе просмотр списка | да | нет (403) | нет (403) |

Права проверяются на сервере функцией `require_role(...)` в начале метода контроллера. Клиент скрывает недоступные кнопки только для удобства.

Тестовые пользователи (пароль `123456`): `admin@vet.example`, `registrar@vet.example`, `doctor@vet.example`.

## Общие ответы с ошибками

Формат один для всех ошибок:

```json
{"error": "Ошибка проверки данных", "errors": {"title": "Причина обращения — от 3 до 200 символов"}}
```

Поле `errors` есть только тогда, когда ошибку можно привязать к полям.

| Код | Когда |
|---|---|
| 400 | тело запроса не JSON-объект |
| 401 | нет токена, токен неверный, отозван или просрочен; при входе — неверная почта или пароль |
| 403 | токен действителен, но роли не хватает прав |
| 404 | нет записи с таким номером или такого адреса |
| 405 | метод не поддерживается; заголовок `Allow` перечисляет доступные |
| 409 | конфликт с данными в базе: врач занят в это время, у животного есть приёмы, повтор телефона или почты |
| 422 | поля не прошли проверку (`errors`); неверный параметр списка (`?animal_id=abc`) |
| 500 | ошибка в коде сервера |
| 503 | «База данных недоступна»: PostgreSQL не запущен |

## Приёмы — /api/appointments

| Поле | Тип | При создании | Описание |
|---|---|---|---|
| id | число | назначает сервер | номер приёма |
| animal_id | число | обязательно | номер существующего животного |
| doctor_id | число или null | нет, по умолчанию null | номер врача; null — врач не назначен |
| title | строка | обязательно | причина обращения, 3–200 символов |
| date | строка | обязательно | дата и время `2026-11-20T10:00` (в базе — столбец `scheduled_at`) |
| status | строка | нет, по умолчанию `scheduled` | `scheduled`, `done` или `cancelled` |
| animal, owner, doctor | строка | только чтение | клички и имена: сервер подставляет их по номерам |

| Метод и адрес | Назначение | Роли | Успех |
|---|---|---|---|
| GET /api/appointments | список | все | 200 |
| GET /api/appointments/{id} | один приём | все | 200 |
| POST /api/appointments | записать на приём | все | 201 + Location |
| PATCH или PUT /api/appointments/{id} | изменить присланные поля | все | 200 |
| DELETE /api/appointments/{id} | удалить приём (медзапись и услуги удалит база) | admin | 204 |

Параметры списка (все необязательны, действуют вместе):
- `status` — статус;
- `animal_id`, `doctor_id` — номера;
- `q` — часть причины без учёта регистра (`%` и `_` ищутся как обычные символы);
- `sort` — `id`, `date` или `title`, с минусом по убыванию (`sort=-id` — новые сверху).

Пример: `GET /api/appointments?sort=-id&status=scheduled&q=%D0%BE%D1%81%D0%BC%D0%BE%D1%82%D1%80` (значения в адресе кодируются, здесь `q=осмотр`).

Создание:

```json
POST /api/appointments
{"animal_id": 4, "doctor_id": 3, "title": "Осмотр клюва", "date": "2026-11-20T15:30"}
```

Ответ 201, заголовок `Location: /api/appointments/9`:

```json
{"id": 9, "animal_id": 4, "doctor_id": 3, "title": "Осмотр клюва", "date": "2026-11-20T15:30",
 "status": "scheduled", "animal": "Кеша", "owner": "Кузнецова О.В.", "doctor": "Сидорова"}
```

Если у врача уже есть приём в это время, ответ 409:

```json
{"error": "У врача уже есть приём в это время", "errors": {"date": "Это время у врача занято, выберите другое"}}
```

Изменение: `PATCH /api/appointments/9` с телом `{"status": "done"}` меняет только статус. `{"doctor_id": null}` снимает врача.

## Животные — /api/animals

Поля:
- `id`;
- `owner_id` (число, обязательно);
- `name` (кличка, 3–100 символов, обязательно);
- `species` (`dog`, `cat`, `bird`, `rodent`, `other`; по умолчанию `other`);
- `breed` (строка или null);
- `owner` (имя владельца, только чтение).

| Метод и адрес | Назначение | Роли | Успех |
|---|---|---|---|
| GET /api/animals, ?owner_id=1 | список, животные владельца | все | 200 |
| GET /api/animals/{id} | одно животное | все | 200 |
| GET /api/animals/{id}/appointments | история приёмов, сначала новые | все | 200 |
| POST /api/animals | добавить | admin, registrar | 201 |
| PATCH или PUT /api/animals/{id} | изменить | admin, registrar | 200 |
| DELETE /api/animals/{id} | удалить; если есть приёмы — 409 | admin | 204 |

## Владельцы — /api/owners

Поля:
- `id`;
- `name` (ФИО, 3–150 символов);
- `phone` (обязателен и уникален, например `+79000000001`);
- `email` (почта или null; пустая строка сохраняется как null).

| Метод и адрес | Назначение | Роли | Успех |
|---|---|---|---|
| GET /api/owners | список | все | 200 |
| GET /api/owners/{id} | один владелец | все | 200 |
| POST /api/owners | добавить; повтор телефона — 409 | admin, registrar | 201 |
| PATCH или PUT /api/owners/{id} | изменить | admin, registrar | 200 |
| DELETE /api/owners/{id} | удалить; если есть животные — 409 | admin | 204 |

## Врачи — /api/doctors

Поля:
- `id`;
- `name` (3–150 символов);
- `specialty` (по умолчанию «терапевт»);
- `phone` (строка или null);
- `is_active` (true или false; в форму записи попадают только работающие врачи).

| Метод и адрес | Назначение | Роли | Успех |
|---|---|---|---|
| GET /api/doctors, GET /api/doctors/{id} | список, один врач | все | 200 |
| POST /api/doctors | добавить | admin | 201 |
| PATCH или PUT /api/doctors/{id} | изменить | admin | 200 |
| DELETE /api/doctors/{id} | удалить; приёмы врача остаются без врача (`ON DELETE SET NULL`) | admin | 204 |

## Пользователи системы — /api/users

Поля:
- `id`, `name`, `email` (уникальна, без учёта регистра);
- `role` (`admin`, `registrar` или `doctor`);
- `password` — только в запросе, не короче 6 символов. В базе хранится `password_hash`, наружу он не отдаётся.

| Метод и адрес | Назначение | Роли | Успех |
|---|---|---|---|
| GET /api/users, GET /api/users/{id} | список, один пользователь | admin | 200 |
| POST /api/users | добавить; повтор почты — 409 | admin | 201 |
| PATCH или PUT /api/users/{id} | изменить; без `password` пароль не меняется | admin | 200 |
| DELETE /api/users/{id} | удалить (себя удалить нельзя — 409) | admin | 204 |
